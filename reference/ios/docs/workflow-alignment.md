# 手机版工作流与设计对应

2026-10-25，基于原生 `792a70d` 补齐。依据工作区 `docs/design/experiment-workflow-v3/README.md`、`app.js` 手机交互和 `live-and-following.md`；正式应用仍为 SwiftUI / Swift Charts，所有数据来自已鉴权 API。

| 设计动线 | 原生实现 |
| --- | --- |
| 关注 / 项目 / 通知 / 账号四个入口 | 各自独立 `NavigationStack`；项目列表 → 项目实验卡片 → 实验沿系统导航逐级返回，不增加“全部项目”跳转。 |
| 项目有明确组织作用域 | 系统组织 Picker，只展示当前所选组织的项目；项目与组织分别读取、分别重试，暂时失败保留已加载内容。 |
| 卡片快速关注 | 卡片右上角原生星标，与打开详情、比较选择分开；沿用条件写、冲突确认与撤销，不修改项目通知订阅。 |
| 真实双指标卡片 | 关注与项目的前六张卡片选择最多两个真实标量。主值来自精确 `summary.last`；Step 小趋势是独立、最多 40 点的 `min_max/v1` 查询，不能替代最新上报。每个指标/context 独立，NaN / ±∞ 明示。 |
| 实验先看曲线 | 首屏最多两张真实 Swift Charts，分段保留缺值；打开指标可查看六种横轴、具体范围和精确点。全部标量目录折叠在次级入口。 |
| 参数 / 记录 / 文件 | 主分段为曲线、记录、文件；“更多 → 参数与信息”由系统导航打开。文件只在打开时读取。摘要、曲线、文件失败各自重试，不清空已有元数据；撤权或身份失效清理相应数据。 |
| 通知保留来源 | 先校验会话、通知权限和实验 incarnation，再在通知栈打开实验；返回保留已加载通知页，单条已读更新不重置分页。 |
| 账号通知开关 | 系统 `.switch` Toggle 控制此设备的推送意愿，复用安全注册与注销；iOS 系统授权、通知预览偏好、项目订阅分别展示和操作。 |

卡片选择只使用现有标量目录，缺少第二条就显示一条，没有指标就显示空状态，不生成占位数值。摘要和曲线分别读取，可能来自不同的已提交水位；界面不将某个 Step 末值冒充最新上报。所有曲线请求携带 incarnation pin，预算拒绝显示局部错误，不截断后宣称完整。

目前曲线在进入、下拉刷新或改变横轴/范围时请求；同轴同范围的暂时失败保留旧图与选点，改变范围则重新加载。关注在应用前台每 20 秒重验证，后台停止；这不等同于曲线持续流更新。本轮没有增加不完整的暂停/继续或固定 revision UI，后续增量调度需另行实现。

Core 测试、通用 SDK 构建与待执行的原生交互断言见 [verification.md](verification.md)。锁屏期间没有启动模拟器或原生 UI；系统返回手势、卡片与开关布局、明暗和 Dynamic Type 的实际验收等待用户解锁后进行，不能用历史 UI 结果代替。
