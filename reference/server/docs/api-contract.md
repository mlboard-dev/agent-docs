# MLBoard implementation contract v0.1

Shared implementation boundary for server, Web and Python client. Coordinate changes across all clients. Existing design schemas remain the target. No mock records in the running app; demo is an explicit client script.

## Runtime

- Go module `mlboard/server`; module minimum Go 1.26, verified toolchain 1.27.3. SQLite default, `--database sqlite --dsn <path>`; PostgreSQL via `--database postgres --dsn <postgres URL>`. Default listen `127.0.0.1:8080`; configurable `--data-dir`, `--web-dir`. Built web served same origin. Health `/healthz`, readiness `/readyz`.
- `web/`: React + TypeScript + Vite + ECharts. Routes client-side; API prefix `/api/v1`. Vite dev proxy to 8080. Credentials cookie; bearer keys for client/agent. JSON errors `{error:{code,message,details?,retryable},request_id}`. IDs strings, int63 revisions/step/seq strings. Times RFC3339 UTC.
- Auth mutation cookie requests must check Origin and CSRF. Login/setup returns `{user,csrf_token}`; GET `/auth/me` returns same; web sends `X-CSRF-Token`. Bearer requests do not require CSRF. All user content is untrusted.
- Before authentication, `strict` Host validation (default) requires the configured public authority. `MLBOARD_HOST_VALIDATION=relaxed` / `--host-validation relaxed` accepts well-formed Host aliases for SDK/Agent calls. It does not relax authentication, scopes, organization/project ACL, browser Origin/CSRF, trusted-proxy rules or the configured OAuth/public-link base. See [LAN and proxy configuration](lan-and-proxy.md).

## Authentication and instance

- `GET /auth/status` → `{setup_required:boolean,providers:[{id,name,enabled}]}`.
- `POST /auth/setup` `{username,email?,password,display_name?}` → user+csrf, creates sole initial admin; username/password login enabled. Min password 15 Unicode chars. One-time setup guarded transactionally.
- `POST /auth/login` `{username,password}` → user+csrf cookie. The `username` field also accepts a local account's email login alias (case-insensitive). `POST /auth/logout`; `GET /auth/me`. User `{id,username,email,display_name,is_admin}`.
- `POST /auth/password` `{current_password,new_password}` rotates credentials/session; admin resets via user management to one-time setup ticket, never returns existing password.
- `GET /auth/providers`; `GET /auth/oauth/{provider}/start` redirects; callback same prefix `/callback`. GitHub and OIDC use persisted instance settings, initially seeded by deployment environment. Disabled providers are unavailable, never simulated login.
- `GET /admin/status`, `GET/POST /admin/users`, `PATCH /admin/users/{id}`, `GET /admin/audit`. Instance admin distinct from project roles; no unauthed admin access.
- `GET/POST /keys`, `DELETE /keys/{id}`. Create `{name,kind:"global"|"project",project_id?,scopes:[...],run_ids?:[],expires_at?}` → `{key:{id,name,kind,project_id,scopes,...},secret}` exactly once. Scopes `projects:write` (global only), `runs:read`, `runs:write`, `data:read`, `data:write`, `dashboards:read`, `dashboards:layout`, `dashboards:write`, `html:publish`, `html:bind_data`, `shares:write`, `members:write`; intersect live project ACL, never scope escalation. `data:write` is ingest. A run-limited key cannot combine project/dashboard/share/member management scopes; layout-only keys cannot change queries, HTML or panel content.

## Projects and experiments

- `GET /projects` → `{projects:[{id,slug,name,description,role,run_count,...}]}`; `POST /projects` `{name,slug?,description?}`; `GET/PATCH/DELETE /projects/{id}`.
- `GET/POST /projects/{id}/members` (add `{username,role}`); `PATCH/DELETE /projects/{id}/members/{user_id}`; roles owner/admin/editor/viewer; last active owner cannot be removed.
- `GET /projects/{id}/runs?search=&path_prefix=&state=&limit=&cursor=&include_summary=` → `{runs:[Run],next_cursor?,total?}`. Segment-aware path prefix, root ungrouped filter. `include_summary` defaults to `true`; explicit `false` returns the same metadata, ordering, ACL and pagination with empty `summary:{}` and performs no history/summary scan. Only one exact `true` or `false` value is accepted. Use metadata mode for navigation and selection; metric columns and summary panels must request summaries. `GET /projects/{id}/categories` → `{categories:[{path,count}]}`.
- `POST /projects/{id}/runs` `{run_id?,run_path,config:{},tags:[],name?}` → Run; exact retry compatible with immutable project/run identity; changed initial body conflicts.
- Run config writes are limited to 65,536 encoded bytes, depth 20 (root=0), and 4,096 JSON nodes including containers/null. Validation preserves numeric representation. Exact legacy create replay and PATCH without config remain compatible; see [request-boundaries.md](request-boundaries.md).
- Run `{id,project_id,run_path,name,state,config,tags,run_version,data_revision,created_at,updated_at,summary:{series_key:{name,context,last,min,max,count,...}}}`. `series_key` is canonical compact JSON `[name,context]`, including empty context, so arbitrary metric names cannot collide with context suffixes; use the entry's `name` and `context` for display/query selectors. `state`: pending/running/finished/failed/stopped. Summary uses primary logical stream, highest session ordinal then seq for repeated step; special values excluded from numeric extrema. No guessed best objective.
- `GET /runs/{id}?include_summary=` uses the same strict/default summary option as the run list; explicit `false` loads one authorized run's metadata with `summary:{}` without scanning history. `PATCH /runs/{id}` with `If-Match` revision (or body `base_revision` string) and `{run_path?,config?,tags?,state?,name?}`; `DELETE /runs/{id}`.
- `POST /runs/{id}/sessions` `{session_id,ordinal:"0",primary_producer:"rank0",resume_parent_session_id?}` → session; `POST /runs/{id}/sessions/{sid}/producers` `{producer_id:"rank0",role:"primary",rank?:0}`; GET sessions lists producers.

## Ingestion and history

- `POST /runs/{id}/events` `{schema_version:"mlboard.batch/v1",events:[Event]}` → `{run_id,data_revision,accepted:[{session_id,producer_id,seq}],duplicate_count}`; ≤512 events/1MiB decoded. Full validation then atomic batch; identity conflicts abort. ACK only after durable commit. Received duplicate has original accepted identity and does not advance revision. Support seq gaps.
- Event `{schema_version:"mlboard.event/v1",run_id,session_id,producer_id,seq:"1",event_time,step?:"0",epoch?:0,elapsed_seconds?:0,session_elapsed_seconds?:0,processed_samples?:"0",fields:[{name,kind:"scalar",value:1.2,value_state:"finite",context?:{},unit?:{kind:"dimensionless"}} | {name,kind,payload,context?:{}}],logs?:[{level,message}]}`. Nonfinite scalar `{value:null,value_state:"nan"|"pos_inf"|"neg_inf"}`. kinds histogram, confusion_matrix, curve, table, text, media. Immutable normalized payload hash for retry; event time fixed on retries.
- `GET /runs/{id}/series` → `{run_id,project_id,run_incarnation,series:[{id,name,kind,context,unit,count,...}]}` (identity is rechecked before delivery; older responses may omit it); `GET /runs/{id}/events?cursor=&limit=` original events, stable pagination. `GET /runs/{id}/logs?cursor=&limit=` → `{logs:[{time,level,message}],next_cursor}`.
- `POST /projects/{id}/query` accepts designed `mlboard.query/v1` (see root docs/design/examples/query.json). Minimum: runs.run_ids/path_prefixes/search; source.kind scalar/histogram/confusion_matrix/curve/table/media and metrics names; x.field step/epoch/elapsed_seconds/wall_time/session_elapsed_seconds/processed_samples and range; read producer/session/duplicate policies; transform raw/downsample min_max; explicit budgets.
- Optional `mlboard.frame-reuse/v1` is advertised in a full private scalar response only when `MLBOARD_QUERY_DELTAS=1`. Supporting clients may then send `reuse:{schema_version,base_token}`; responses use exact row upserts/removals/order or a full reset. Ordinary clients, public queries and pagination keep full frames. Authentication, identity and budgets run before every response; see [query-frame-reuse.md](query-frame-reuse.md). Diagnostic request IDs are always in `X-Request-ID`; a body copy is optional.
- Query source budgets count original records before canonical duplicate resolution and display downsampling. The server first performs bounded counts using the exact run revision, metric/context, producer/session and safe step predicates; an oversized selection returns `422 budget_exceeded` with `details.limit:"max_scanned_points"` before materializing source payloads. Accepted queries also pay this count cost. Private run selection is independently bounded at 1,000; series at 2,000; scanned source records at 10,000,000; public share selection retains its separate 50-run bound; data work defaults to 60 seconds with an instance-configured ceiling of 1..600 seconds.
- Result designed `mlboard.query-result/v1`: `{query_id,result_etag,complete,consistency:{snapshot_id,expires_at,resolved_runs},applied,frames:[{frame_id,kind,row_count,fields,columns,meta:{run_id,metric,context,logical_stream}}],diagnostics,page:{next_cursor,returned_rows}}`. scalar columns `run_id,step,x,value,value_state,event_ref,elapsed_seconds`; x follows the selected axis (int64 decimal strings for Step/processed samples, float64 for numeric axes, RFC3339 for wall_time). `elapsed_seconds` is the original event's recorded Run-relative time, nullable if absent and independent of x. Keep actual coordinate/source; reject unsupported operations, never silently ignore requested semantics. Page fixed revisions and live ACL. Number of points, scan and bytes bounded; min-max retains actual extrema. `budget.timeout_ms` is optional: execution resolves omission to the instance read default/ceiling (60s by default, configurable 1..600s). Explicit positive budgets may shorten that deadline; values above the instance ceiling return `422 validation_error`. Static query/dashboard schemas allow up to 600000ms for portability. Stored explicit values such as 3000ms are never silently rewritten; newly generated Web queries omit the field. Query final authorization/identity checks and snapshot work remain within the effective query budget. Capabilities expose `query_timeout_ms`, `query_default_timeout_ms` and `share_preview_recheck_timeout_ms` under `limits`.

Query source-work defaults/ceilings are 1,000 Runs, 2,000 series and 10,000,000 original records across the whole selection, including superseded duplicates. Output limits remain 250,000 points / 8 MiB and concurrency stays 4 origin queries. Web-generated charts use a shared 10,000-point output budget, distributing samples across all selected Runs rather than returning every original point. Explicit smaller saved budgets remain in force. Private selection/save accepts 1,000 Runs; public share grant limits remain separate at 50 Runs.
- `GET /projects/{id}/updates` SSE data `{kind,project_id,run_id?,data_revision?,run_version?,cursor}`; shared stream, bounded buffer, reset_required if behind, revoke actively. `/realtime` WS equivalent subscriptions; `/ingest/stream` optional transport for same ingest contract only if capabilities advertises it.
- Optional cross-instance Valkey hints emit project-scoped `reset_required`, with no run/dashboard/user payload. Cursors in this mode are opaque instance-scoped replay positions; a different instance/old cursor resets. Best-effort hints have a 27–30s active-subscription reconciliation fallback, not durable event delivery. Default off; see [realtime-cluster.md](realtime-cluster.md).

## Files, structured data, dashboards

- `POST /runs/{id}/artifacts` multipart file + `name`, `kind`, `metadata` JSON and optional `artifact_id` UUID → `{id,name,kind,size,mime,...}`; size bounded, stored under opaque path, durable before response. Client may assign stable offline artifact_id, include it in immutable event payload, then upload before the event. Same ID/bytes/metadata retry returns existing; changed body or run/project conflicts. `GET /runs/{id}/artifacts` → `{artifacts:[]}`; `GET /artifacts/{id}/content` authorized streaming/Range, untrusted HTML attachment download not same-origin active document. `/artifacts/{id}` metadata.
- File storage is deployment-configured `local` or `s3` (RustFS recommended). Per-artifact backend/location is persisted; wire payloads and authorization stay the same. Content GET/HEAD streams through MLBoard with ETag and up to 16 byte ranges. S3 requests occur outside SQL transactions. Temporary storage failures return retryable `503 artifact_storage_unavailable`, saturated upload capacity returns `429 artifact_busy`. See [storage.md](storage.md).
- Uploads pin the authorized starting project/run incarnation and recheck it before retry delivery or SQL publication. Defaults: 600s total, 30s body inactivity, 8 global/2 per account/4 per project concurrent uploads. Body receive timeout is `408 request_timeout`; changing only data revision does not invalidate an upload. Ordinary JSON, public/private queries and MCP have a separate finite 30s receive default; finite response output starts its own 60s default only when writing begins. Realtime keeps its heartbeat/stream policy. See [request-boundaries.md](request-boundaries.md).
- `GET/POST /projects/{id}/dashboards`; create `{title,spec?}` → Dashboard. `GET /dashboards/{id}` → `{id,project_id,title,revision,etag,spec}`; `PUT /dashboards/{id}` `{spec}` requires If-Match. Spec matches mlboard.dashboard/v1; panel options for timeseries, table, histogram, confusion_matrix, roc, precision_recall, text, html. Implemented registry only.
- Optional `view.presentation.panels[panel_id].size` is `{width,height}` in integer CSS pixels: width 240..1600, height 240..1000. Height is the base card height before additional legend space. Both dimensions are required when `size` is present. It overrides the panel's base layout size; omission uses the active automatic/global or manual-grid layout. Explicit `resize_panel` replaces the grid `w`/`h` and clears only that panel's pixel size override, preserving other presentation settings, panels and queries; `move_panel` retains it. This presentation-only setting retains `mlboard.view-presentation/v1`, the existing layout permission and revision checks, and JSON round-trip support.
- `POST /dashboards/{id}/validate` `{spec}` → validation; `/preview` accepts `mlboard.dashboard-change/v1`, returns `{preview_id,base_revision,spec,diff,valid}`; `/apply` `{preview_id,client_request_id}` + If-Match → new Dashboard, idempotent request. Named operations move_panel,resize_panel,add_panel,remove_panel,update_panel,upsert_section,remove_section,upsert_query,remove_query,set_selection,set_title,set_section_order,set_panel_section,set_view; verify complete non-overlapping layout.
- `GET /dashboards/{id}/history`; `POST /dashboards/{id}/restore` `{revision}` + If-Match. `POST /dashboards/import` `{project_id,format:"json"|"xml",content}`; `GET /dashboards/{id}/export?format=json|xml`. XML safe parser (no external entities), same validation.
- GET `/dashboards/{id}/panels/{panel_id}/render?revision=R` serves a separately fetched document with response CSP sandbox allow-scripts, no network, no same-origin, restrictive Permissions-Policy, and revision/auth checks. HTML panel rendering uses sandbox iframe without allow-same-origin; strict CSP no network; only sanitized bounded query_ref data via verified postMessage/channel; never pass auth tokens. If HTML content is inline, spec options `html` string; support `artifact_id` for stored content with same isolation. HTML publishing requires html:publish and project edit authorization; changing bound query/selection/capabilities requires html:bind_data; layout-only changes never grant HTML publication. Queries must come from permitted declared query_refs.
- `GET /capabilities`, `/schemas`, `/registry`; expose actual implemented versions/limits. Agent HTTP uses same dashboard/query APIs; `/mcp` JSON-RPC tools/list + tools/call thin wrapper, same auth/ACL and preview/apply.

## Sharing and mobile

- `GET/POST /projects/{id}/shares`; create `{target_type:"project"|"run",run_id?,title?,run_ids?:[],run_incarnations?:{run_id:incarnation},metrics?:[],include_metrics?:true,include_config?:false,config_fields?:[],include_media?:false,expires_at?}` → `{share,secret,url}`. Revocation `DELETE /shares/{id}`. Pins require an exact one-to-one match with `run_ids` and the current project/incarnation; a missing or rebuilt run returns 404. An explicit pinned empty selection stays empty. Legacy unpinned project creation with no IDs freezes the current bounded selection; it is not a dynamic grant.
- `POST /projects/{id}/shares/preview` accepts the same proposed projection plus optional `summary_run_ids:[...]` and requires the same live sharing authority, instance switch and CSRF/origin checks as creation. It is an authenticated, stateless read: no share, grant, secret, URL or create-audit record is produced. Response `{preview:true,share:{title,target_type,expires_at,metrics,include_metrics,include_config,config_fields,include_media},project:{id,name,slug},runs:[publicRunProjection...],selection:{run_ids,run_incarnations},budget}` uses the same whitelist/metric filter as public run output. Hidden config and all file contents/URLs are absent; `include_media` only previews that permission. Publishing can send the returned selection and normalized expiry; preview is not a credential and neither publication nor anonymous access skips authorization.
- `include_metrics:false` removes summary values and disables every public query source; metadata remains available without reading history. File downloads still require the independent `include_media` permission. `config_fields` is a whitelist of complete top-level config values (up to 200 unique nonempty keys of 256 bytes). Omitted/null preserves legacy all-fields behavior only when `include_config:true`; `[]` explicitly exposes zero fields. Preview, create/list and public policy responses preserve null versus `[]`. Public query filters may only reference permitted config keys, including decoded JSON Pointer segments; hidden fields cannot be inferred by filtering. Preview summary requests with metrics disabled are rejected. Schema 13 preserves existing shares. New restricted grants use binding version 2, so identity-aware older binaries reject them rather than silently broadening access on rollback.
- Preview defaults to metadata only (`summary_status:"not_requested"`). `summary_run_ids` must be unique members of that selection, at most 3 per request. Each requested summary is exact at its captured revision or has `summary_status:"error",summary:{},summary_error:{code:"query_timeout"|"budget_exceeded"|"unavailable",limit?}`; raw storage messages are not exposed. The work window defaults to 60 seconds (`MLBOARD_READ_TIMEOUT_SECONDS` / `--read-timeout`, 1..600s), with a separate final ACL/identity check defaulting to 10 seconds (`MLBOARD_READ_RECHECK_SECONDS` / `--read-recheck-timeout`, 1..120s). The final check derives from the original request context, respects client cancellation/shorter parent deadlines and fails closed; it is not skipped when summary work times out. The 200-series catalog and cumulative 250,000 scalar source-record admission limit guard summary calculation, even with a metric whitelist. Catalog aggregation may itself scan more source records; its cost is timeout-bounded, not represented as a strict 250,000-record scan cap. At most 50 runs and 2 MiB of projected JSON are returned; selection/payload violations return 422 `budget_exceeded`. The response advertises these limits in `budget`.
- Public no-login `GET /api/public/v1/shares/{secret}` → `{share,project,runs,dashboards}` restricted projection; `GET .../runs/{id}`, `POST .../query`, `GET .../artifacts/{id}/content` restricted independently of logged-in cookies. Generic unavailable response when invalid/revoked. Public web `/s/{secret}`.
- Responsive web supports complete experiment navigation and curves on phones; same API. Persist notification inbox and subscriptions in server with device adapter boundary, native APNs requires deployment credentials; no fabricated sends.

## SDK and local mode

- Python package `mlboard`, dependency-light. `init(project,run_path,config=None,tags=None,spool_dir=...,sync="off",server=None,api_key=None,mode="safe",retention="record",run_id=None,...)`; bounded process-local enqueue; independent collector writes SQLite history and uploads. `run.log(dict,step=...,epoch=...)`, structured helpers, `log_media`, `log_text`, `status`, `finish(timeout=2,wait_for="local",state="finished")`; context manager preserves training exceptions.
- Collector resolves project slug via GET projects; create project only with explicit create permission. Stable offline run/session/producer/seq. Outbox ACK drops references, record history remains. Global/project bearer keys from env or explicit args, never log them.
- CLI `python -m mlboard sync <logdir> --server ...` and `serve --logdir ... --host 127.0.0.1 --port 8081` local read API + viewer, independent from center. Never write source DB from viewer; safe Host/Origin checks. Center web viewer asset reuse preferred; minimal bundled functional viewer fallback may use same public shapes.
- `examples/demo.py` produces actual experiments (deterministic synthetic metrics explicitly demo), writes via SDK, optionally uploads; no builtin default data in server.

## Organizations and administration

Organization and project management authority is separate from experiment data access. Instance administrators and organization owners/admins do not automatically read runs, queries, shares or artifacts. They use the organization project directory to grant an explicit project membership first. Every project data API and global key intersects that live membership and its organization membership.

- `GET /organizations` → `{organizations:[{id,slug,name,description,revision,etag,role,can_manage,created_at,updated_at}]}`. Every account, including instance administrators, sees only organizations it has explicitly joined. `role` is the actual membership role; `can_manage` includes instance administrator authority only after membership is checked. `POST /organizations` `{slug,name,description?}` accepts any active signed-in account and atomically creates it as organization owner. API keys cannot create organizations.
- `GET/PATCH /organizations/{id}` first requires live organization membership; unjoined accounts, including instance administrators, receive 404. PATCH `{name?,description?}` additionally requires an organization owner/admin or a joined instance administrator and `If-Match: "org:REVISION"`; missing precondition is 428 and stale revision 412. Revision is a decimal string. Slug is immutable.
- `GET/POST /organizations/{id}/members`, `PATCH/DELETE /organizations/{id}/members/{user_id}`. Add accepts exactly one of `username` or `user_id`, plus `role`. Roles are `owner`, `admin`, `member`. The caller must already belong to the organization; instance administrators cannot self-join through this route. Organization admins manage nonowners and cannot grant owner; organization owners and joined instance administrators may manage owners. The last active owner cannot be removed, demoted or disabled.
- `GET /organizations/{id}/projects` is a management directory for organization owners/admins and joined instance administrators. It returns `{projects:[{id,organization_id,slug,name,description,project_role,created_at,updated_at}]}` with no experiment data or run summaries. `project_role` is the caller's explicit project membership or an empty string.
- `GET /projects?organization_id=ID` still returns only explicit project memberships. Project objects include `organization_id`. POST `/projects` adds `organization_id`; omission is accepted only when the caller has exactly one eligible organization. Project slugs remain unique across the whole instance; project IDs are stable SDK identifiers.
- Project roles are `owner`, `admin`, `editor`, `viewer`. Project admins edit experiments, metadata, dashboards, shares and nonowner project members. Project owners additionally manage project owners and delete the project. Organization owners/admins and joined instance administrators can use the existing project member routes to grant explicit project `admin`/`editor`/`viewer` roles; organization owners and joined instance administrators can also grant project owner. Every recipient must already be an active member of that organization. Project member POST accepts exactly one of `username` or `user_id`, plus `role`.
- `GET /projects/{id}/keys` and `DELETE /projects/{id}/keys/{key_id}` allow explicit project owners/admins with a browser session to list metadata/revoke project-scoped keys; secrets are never returned. Organizational management alone does not grant this data authority. Users still create their own keys through `/keys`.
- Removing an organization member removes that organization's project memberships, project-scoped keys and notification subscriptions. A sole project owner must first transfer ownership. Global keys remain but immediately lose access under the live ACL. The last active project owner cannot be removed or disabled.
- Setup additionally accepts `instance_name`, `organization_name`, `organization_slug`. These and the initial administrator/organization owner are committed together. Omitted names default to `MLBoard`, `Default`, `default` for compatibility. Existing v1 projects migrate to `org_default` with their original project ACL unchanged; an existing active instance administrator owns the default organization.

Local operator recovery is available through `mlboard admin list-admins` and `mlboard admin reset-password --username NAME --password-stdin` (or hidden TTY input). Backend, DSN and data-directory flags/environment are shared with normal startup. The target must already be an instance administrator; role and disabled state do not change. Reset revokes all sessions, API keys and reset tickets transactionally. The command opens storage directly and is independent of OAuth settings decryption.

## Persistent instance settings and account registration

`GET/PATCH /api/v1/admin/settings` require a live instance administrator browser cookie; keys are rejected. PATCH requires same-origin CSRF and the exact GET `etag` in `If-Match`. Missing precondition returns 428, stale revision 412. Settings are persisted transactionally and apply at runtime, including across server restarts.

The GET body is:

```json
{
  "revision": "1",
  "etag": "\"settings:1\"",
  "instance": {"name":"MLBoard","description":"","default_language":"zh-CN","default_theme":"system"},
  "registration": {"enabled":false},
  "access": {"project_creation":"org_members","public_sharing_enabled":true,"share_default_days":7,"share_max_days":365},
  "credentials": {"session_days":7,"global_key_default_days":7,"project_key_default_days":30,"key_max_days":365},
  "oauth": {
    "github": {"enabled":false,"client_id":"","client_secret_configured":false,"available":false,"unavailable_reason":"disabled","callback_url":"https://example.org/api/v1/auth/oauth/github/callback"},
    "oidc": {"enabled":false,"issuer":"","client_id":"","client_secret_configured":false,"available":false,"unavailable_reason":"disabled","callback_url":"https://example.org/api/v1/auth/oauth/oidc/callback"}
  },
  "public_url":"https://example.org"
}
```

PATCH accepts partial sections directly, for example `{"instance":{"name":"Research"},"registration":{"enabled":true}}`. Revision, etag, public_url, callback_url, available, unavailable_reason and client_secret_configured are read-only. Unknown fields are rejected. `instance.name` is nonblank and ≤120 bytes; description ≤2000 bytes. Language is `zh-CN` or `en`, theme `system`, `light` or `dark`. Session lifetime is 1–30 days; share/key defaults and maxima are 1–365 days and each default must not exceed its maximum. Tightening lifetimes affects newly issued credentials/links; existing expiry timestamps are not rewritten.

`project_creation` is `org_members` or `org_admins`. It restricts creation inside an organization; it never creates organization membership implicitly. Browser instance administrators who are members can create projects under either policy. Keys use only the owner's organization role and their declared project-creation scope.

Each provider PATCH additionally accepts `client_secret`. Omitted or empty strings preserve the stored secret; `clear_client_secret:true` explicitly removes it. Nonempty secret plus clear is rejected. Disable a provider when clearing a required secret. Enabled providers must have a trusted public origin, client ID, secret, and (OIDC) a valid HTTPS issuer or loopback HTTP issuer. `available` means that complete configuration is present; actual discovery/token/identity checks still run during login and may fail. Secrets and ciphertext never appear in settings responses or audit details; audit records changed field names only.

`GET /auth/status` returns `{setup_required,registration_enabled,instance,providers}`. `instance` contains only the four safe profile/display fields. Effective registration is false before setup. `POST /auth/register` accepts `{username,password,email?,display_name?}`, follows the same NFC 15–128 character password policy as setup, and returns 201 `{user,csrf_token}` plus a session cookie. It creates an ordinary account with no organization or project memberships. Registration is closed by default. One shared switch controls local registration and new OAuth subjects; closing it does not block local login or already-bound external identities. Bootstrap must already have an active administrator.


Settings environment values seed only the first settings record. `MLBOARD_REGISTRATION_ENABLED=true` is the explicit bootstrap registration opt-in. The former OAuth-only `MLBOARD_OAUTH_ALLOW_SIGNUP` no longer opens signup; use the persisted unified switch. Provider client ID/secret/issuer environment values are imported once, then the database is authoritative. Public URL, database and storage configuration remain deployment-owned.

## Single-use registration invitations

Instance administrator **browser sessions** manage invitations; API keys and organization/project administrators do not have this permission. Mutations require same-origin and CSRF checks.

- `POST /admin/registration-invites` accepts `{username,email?,expires_in_days?}`. Username is required (same ASCII identifier rules, up to 128 characters), email optional; expiry defaults to 7 days and is limited to 1–30 days. Returns 201 `{invitation,registration_url}`. The full link is returned once; the database stores only a SHA-256 token digest. The URL uses configured public origin and `/register#invite=...`, so the token is not part of HTTP paths or referrers.
- `GET /admin/registration-invites` returns `{invitations:[...]}`, newest first, up to 1000 records. Records contain `id,username,email,created_at,expires_at,status` and optional `used_at,revoked_at`; status is `pending|used|expired|revoked`. No bearer tokens or digests are returned.
- `DELETE /admin/registration-invites/{id}` revokes a pending invitation. Repeating revocation is idempotent; a used invitation returns 409.
- `POST /auth/registration-invites/inspect` accepts `{token}` and returns `{username,email,expires_at}`. This public, same-origin operation is read-only, uncached and may be repeated. POST keeps the token out of access-log URLs. Invalid, used, expired or revoked links return 410 `invitation_unavailable`.
- `POST /auth/register` also accepts `{invitation_token,password,display_name?}`. A valid invitation permits signup while open registration is disabled. Username/email are taken from the invitation; if supplied, conflicting values are rejected. Password policy remains NFC 15–128 characters. User insertion, session issuance and conditional invitation consumption commit together. Failed requests do not consume it; simultaneous valid submissions allow only one 201 response. Success returns the same `{user,csrf_token}` and cookie as ordinary registration, without implicit organization/project membership.

Pending invitations reserve their username and optional email against other local registrations, admin account creation and duplicate invitations until used, revoked or expired. Emails are trimmed, validated as ordinary ASCII mailbox addresses, and lowercased for local sign-in; dots and plus suffixes are not rewritten. Local email aliases have a unique database index, while usernames keep their existing case-sensitive semantics. Email sign-in does not link OAuth identities by email. Migration v3 retains historical metadata and only enables unambiguous valid email aliases; duplicate/invalid legacy emails remain username-only rather than selecting an arbitrary account.

Token handling follows the single-use, expiration and secure-storage principles in the [OWASP URL-token guidance](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html#url-tokens), applied here to new-account invitations.

Run objects expose a server-generated immutable `run_incarnation`. A deleted public `id` may be reused, but the replacement always receives a different incarnation. Reads capture `(project_id,id,run_incarnation,data_revision)`; each history adapter validates and filters that reference in its own consistent SQL snapshot, and HTTP delivery rechecks current authorization and identity. Old query/event/list cursors reject replaced identities instead of switching to the replacement. Event cursors also hold the captured upper revision.

New public shares and static run-scoped API keys bind each run's incarnation. Schema-v7 migration invalidates legacy public shares and static run grants whose historical identity cannot be established; recreate those credentials deliberately. Broad project/global keys retain their existing scope semantics. Session/producer/event/point and artifact associations inherit the incarnation through enforced cascade foreign keys to the immutable run root; migration does not duplicate incarnation into every point. Tombstones prevent reusing an incarnation. Restored/imported databases must rotate their storage epoch before joining an existing shared cache; rotation also invalidates persisted snapshots and static grants.

`POST /projects/{id}/runs` and `PATCH /runs/{id}` return committed metadata and its `ETag` without reading history. Their `summary_status:"pending"` means the exact summary was not loaded for this response; `summary:{}` is not an exact empty result. Fetch default run GET for `summary_status:"ready"`; metadata-only GET/list use `summary_status:"not_requested"`. Create retries with identical initial content return the current metadata/ETag and do not repeat creation; PATCH retries with the old If-Match receive 412.

Create/PATCH/delete enqueue typed run notifications in the same SQL transaction. A local background outbox publishes after commit and marks delivery afterward, with stable `event_id` plus `run_incarnation`, `run_version`, and `data_revision`; delete retains the deleted incarnation. Pending records survive process restart. Delivery is at least once: a crash between publish and acknowledgement may replay the same event ID. It is a hint for revalidation, not a second business write. The initial outbox broadcasts to its local process hub; cross-instance live fanout is a separate capability, and published records are currently retained.

User following endpoints and conditional update semantics are documented in [following.md](following.md). Their private SQL-backed SSE uses user versions, never project subscriptions. Notification objects now expose `run_incarnation`; historical Run notifications with no trusted binding fail closed rather than guessing the current run. APNs includes incarnation only as a routing hint; clients still fetch the notification and reauthorize the destination.

### Filtered run lists

`GET /projects/{id}/runs?filters=<URL-encoded JSON array>` applies the same field/operator/null/JSON Pointer semantics as `query.runs.filters`, before pagination. Conditions are ANDed with state/search/path-prefix and constrained by current permissions. Up to 50 conditions and 16 KiB JSON; malformed, repeated or unsupported filters return 422. Cursors bind normalized conditions and sort; changing conditions rejects the old cursor. Search/config/tag filtering scans metadata only, bounded to 10,000 candidates per page and the configured data-read deadline (default 60 seconds). Exceeding this returns `budget_exceeded` / `run_scan`, never an apparently complete partial result. Use a narrower path prefix or state when the candidate set is too large. Summary-metric filtering remains unsupported.

## Exact config numbers

Run config retains JSON number/string semantics. Config-only decoding preserves original number tokens (including int64 boundaries, longer integers, exact decimals and exponents); scalar metrics keep their existing floating-point contract. Number `9007199254740993` and string `"9007199254740993"` are different. Numeric filter equality compares exact decimal values (`1`, `1.0`, `1e0` are equal); replay/export preserves original numeric lexemes independently of that equality.

New or changed configs retain the 64 KiB / depth 20 / 4096-node write limits. Existing configs remain readable and metadata-only PATCH does not convert their numbers through float64. `GET /runs/{id}/config` downloads the authorized original stored bytes as an attachment, including legacy values that cannot be parsed/expanded in a client. The normal run/detail/list and reviewed public config projection continue using ordinary JSON numbers, without a new envelope.

A PATCH with explicit `config` requires `MLBoard-Config-Numbers: exact-v1` when either the current or replacement config includes number tokens that an ordinary binary64 client might change. Otherwise the server returns 409 `config_precision_required` without changing the run. The header declares a lossless codec; it is not authorization. Omitting config for name/state changes remains compatible. POST/create retries continue accepting exact JSON from older SDKs. Updated Web/native/Python clients use a dedicated exact config reader/writer; Web/native also reject unsafe binary64 integers supplied programmatically rather than pretending to recover lost digits.

Config filter values in run URLs, query/dashboard selectors and saved analysis definitions retain the same exact number semantics. This does not turn chart axis ranges, metric samples, layout or unrelated JSON into arbitrary precision values. Web comparison/edit/clone/export paths retain exact tokens; only explicitly safe values become numeric config chart axes. Old clients that cannot preserve config numbers should use raw download and update their codec before editing config.
